## 1. 任务目标

实现 `FuturesDataAggregator` —— Phase 14 的核心交付物之一，统一调度：

1. **5 级 K 线主路径降级**：`DUCKDB_CACHE → TQ_LOCAL → TQ_PYTHON → AKSHARE → SYNTHETIC`
2. **字段增强层并行**：`WIND + IFIND` 在 K 线主路径之后并行补充 `settle/oi_change/pre_settle/hold`

5. **DuckDB 缓存**：新鲜度过滤 + 自动写入 + 透明回放

端到端验证：5 级降级链 + 熔断器状态机 + 字段增强优雅降级 + trace_id 贯通。

### 3.2 5 级 K 线降级路径

| 优先级 | 源 | 角色 | 触发条件 |
|:------:|:--|:-----|:--------|
| 1 | `DUCKDB_CACHE` | 本地缓存（最便宜） | 缓存日期 ≥ today - `cache_max_age_days` |
| 2 | `TQ_LOCAL` | 通达信本地 HTTP | 缓存未命中 + 熔断器 CLOSED |
| 3 | `TQ_PYTHON` | 通达信 Python SDK | TQ_LOCAL 失败 + 熔断器 CLOSED |
| 4 | `AKSHARE` | 新浪主连（兜底） | TQ 全部失败 + 熔断器 CLOSED |
| 5 | `SYNTHETIC` | 合成数据 | 所有源失败（保证系统可运行） |

```python
def get_ohlcv(self, symbol, days, trace_id):
    # 1) 尝试缓存
    df = self._try_cache(symbol, days)
    if df is not None and not df.empty:
        return self._enhance_fields(self._set_source(df, "DUCKDB_CACHE"), symbol, trace_id)

    # 2) 依次尝试每个 K 线源
    for source in self.sources:
        if self._is_circuit_open(source.source_name):
            continue
        try:
            df = source.fetch_ohlcv(symbol, days, trace_id=trace_id)
        except Exception as e:
            self._record_failure(source.source_name, str(e))
            continue
        if df is not None and not df.empty:
            self._record_success(source.source_name)
            df = self._set_source(df, source.source_name)
            if len(df) > days:
                df = df.tail(days).reset_index(drop=True)
            self._write_cache(df)
            return self._enhance_fields(df, symbol, trace_id)

    # 3) 所有源都失败 → 合成数据
    return self._synthesize(symbol, days, trace_id)
```

### 3.3 熔断器状态机

```
            ┌──────────────┐  连续 N 次失败   ┌──────────────┐
   正常 ◀─▶ │   CLOSED     │ ───────────────▶ │     OPEN     │
            │ (consecutive │                  │ (skip 源调用) │
            │  failures=0) │                  └──────┬───────┘
            └──────────────┘                         │ 冷却 6 小时
                    ▲                                ▼
                    │ 探活成功                ┌──────────────┐
                    │                  ┌─────▶ │   HALF_OPEN  │
                    │                  │       │ (允许 1 次)   │
                    │                  │       └──────┬───────┘
                    │ 探活失败          │              │ 探活失败
                    └──────────────────┘              ▼
                                                重新 OPEN
```

**关键参数**：

| 参数 | 默认值 | 说明 |
|------|------|------|
| `circuit_breaker_threshold` | 5 | 连续失败 N 次触发熔断 |
| `circuit_breaker_cooldown_seconds` | 21600 (6h) | 熔断冷却时间 |
| `cache_max_age_days` | 1 | 缓存新鲜度阈值 |

**关键行为**：

| 场景 | 行为 | 影响 |
|------|------|------|
| 源调用 `fetch_ohlcv` 抛 `ConnectionError` | 计入失败计数器 | 累计到阈值开启熔断 |
| 源返回 `None` 或空 DataFrame | **不计入**也不重置 | 区分"失败"和"无数据" |
| 源成功返回非空 DataFrame | 重置失败计数器 | 避免正常源被误熔断 |
| `_is_circuit_open()` 返回 True | 跳过该源 | 加速降级到下一源 |
| 冷却时间到 | 半开探活 | 成功 → CLOSED；失败 → 重新 OPEN |

### 3.4 字段增强层（独立并行）

```python
def _enhance_fields(self, df, symbol, trace_id):
    """用 Wind/iFinD 字段增强层补充 settle/oi_change 等。

    注: 字段增强层不修改 K 线主路径的行数；仅尝试补充缺失列。
    失败不抛异常（K 线主路径已成功，增强是锦上添花）。
    """
    for enhancer in self.enhancers:
        try:
            if self._is_circuit_open(enhancer.source_name):
                continue
            enrich_df = enhancer.fetch_ohlcv_or_none(symbol, days=len(df), trace_id=trace_id)
            if enrich_df is not None and not enrich_df.empty:
                self._record_success(enhancer.source_name)
                # 用 enhancer 的字段覆盖主路径的对应列
                for col in ("settle", "pre_settle", "oi_change", "hold"):
                    if col in enrich_df.columns and col in df.columns:
                        df[col] = enrich_df[col].values[:len(df)]
        except Exception as e:
            self._record_failure(enhancer.source_name, str(e))
    return df
```

**关键设计**：

1. **独立熔断器** —— 字段增强层失败不影响 K 线主路径
2. **不修改行数** —— 仅按位置覆盖 `settle/oi_change/pre_settle/hold` 4 个字段
3. **优雅降级** —— `try/except` 包裹任何异常，K 线主路径已成功返回
4. **trace_id 贯通** —— 字段增强层调用同样携带 trace_id

### 3.5 DuckDB 缓存设计

```python
def _try_cache(self, symbol, days) -> Optional[pd.DataFrame]:
    """尝试从 DuckDB 缓存读取 K 线。"""
    if self.db_path is None or not self.db_path.exists():
        return None
    cutoff = (pd.Timestamp.now() - pd.Timedelta(days=self.cache_max_age_days)).date()
    # 品种匹配兼容：缓存中可能是 RB0.SHFE 也可能是 RB0
    sym_variants = [symbol, f"{symbol}.SHFE", f"{symbol}.DCE",
                    f"{symbol}.CZCE", f"{symbol}.CFFEX"]
    df = con.execute("""
        SELECT * FROM kline_cache
        WHERE symbol IN (?,?,?,?,?) AND date >= ?
        ORDER BY date DESC LIMIT ?
    """, [*sym_variants, cutoff, days]).df()
    return df if not df.empty else None
```

**关键特性**：

1. **新鲜度过滤** —— `date >= today - cache_max_age_days`（默认 1 天）
2. **品种多写法** —— 兼容 `RB0` / `RB0.SHFE` / `RB0.DCE` 等
3. **自动写入** —— 拉取外部源成功后透明写入缓存
4. **降级透明** —— `_write_cache` 失败不抛异常（缓存是次要路径）

```python
def _synthesize(self, symbol, days, trace_id) -> pd.DataFrame:
    """生成合成 K 线数据（保证系统可运行）。

    仅在所有 5 级源全部失败时触发。
    标记 source=SYNTHETIC 以便下游识别。
    """
    np.random.seed(hash(symbol) % 2**31)
    ...
    return pd.DataFrame({
        ...
        "source": DataSource.SYNTHETIC.value,
        "trace_id": trace_id,
    })
```

**关键设计**：

1. **可重现性** —— `np.random.seed(hash(symbol))` 保证相同品种每次合成数据一致
2. **明确标记** —— `source=SYNTHETIC` 让下游（因子引擎）可识别并跳过
3. **schema 完整** —— 17 列 FTS schema 严格对齐
4. **trace_id 注入** —— 合成数据也带 trace_id
