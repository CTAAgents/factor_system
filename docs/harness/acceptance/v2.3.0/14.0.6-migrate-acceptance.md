## 6. 设计要点

### 6.1 幂等性策略

- **表**: `CREATE TABLE IF NOT EXISTS` + `information_schema.tables` 探测
- **列**: `PRAGMA table_info` 探测 + 仅 `ALTER ADD COLUMN` 缺失列（DuckDB `ALTER ADD COLUMN` 不支持 IF NOT EXISTS）
- **索引**: `CREATE INDEX IF NOT EXISTS` + `duckdb_indexes()` 探测

### 6.2 数据安全

- `migrate_schema` 只动 schema，不动数据
- 旧版 DB 上 `ALTER ADD COLUMN` 不重写已有记录，新增列默认 NULL
- 唯一数据变更入口是测试用例的 `INSERT INTO`（用于 fixture）

### 6.3 HARNESS 合规

- ✅ §5.1 文档先行：`docs/harness/13-futures-data-source-integration.md` 已在 14.0.1 任务更新
- ✅ §5.3 契约优先：返回 dict 严格 3 键
- ✅ §5.4 测试随重构：100% 覆盖率
- ✅ §5.5 trace_id 全链路：3 张表均含 `trace_id` 字段
- ✅ §5.6 角色边界：仅管 schema，不参与数据采集/因子/组合
