## 1. 任务目标

实现同花顺 iFinD MCP 适配器，作为字段增强层（不参与 K 线主路径 `DUCKDB_CACHE → TQ_LOCAL → TQ_PYTHON → AKSHARE`），主要承担两个角色：
1. **EDB 宏观/产业链数据**（独家能力，写入 `edb_cache` 表）
2. **期货全字段补充**（`hold/settle/pre_settle/oi_change` 等）

端到端验证 K 线字段与 EDB 宏观数据能正确写入 `kline_cache` / `edb_cache`，并处理 iFinD 特有的字段命名风格（camelCase 如 `openInterest` / `preSettle`）和代码格式（`SHF` 而非 `SHFE`、`CFX` 而非 `CFFEX`）。

## 3. 实现要点

### 3.1 类结构

```python
class IFindSource(BaseFuturesSource):
    source_name: str = "IFIND"

    # 字段增强层 — 不参与 K 线主路径熔断
    def is_available(self) -> bool            # 探活（不抛异常）
    def fetch_ohlcv(...)                       # 抛 SourceUnavailable
    def parse_ohlcv(...)                       # 公开方法，可独立测试
    def parse_ohlcv_or_none(...)               # 异常 → None
    def fetch_ohlcv_or_none(...)               # 覆写基类，吞 SourceUnavailable
    def fetch_quote(...) / parse_quote(...)
    def fetch_edb(...)                         # iFinD 独家能力
```

### 3.2 iFinD 期货代码后缀（与 TQ/Wind 不同）

| 交易所 | TQ-Local | iFinD | 差异 |
|--------|---------|-------|------|
| 上期所 | `RB0.SHFE` | `RB0.SHF` | 去掉 `E` |
| 大商所 | `M0.DCE` | `M0.DCE` | 一致 |
| 郑商所 | `TA0.CZCE` | `TA0.CZC` | 去掉 `E` |
| 中金所 | `IF0.CFFEX` | `IF0.CFX` | 缩写为 3 字母 |

> 完整匹配顺序（避免 TA 误判为 T+CFFEX）:
> 1. CFFEX 2 字母 (IF/IH/IC/TF/TS/TL) → CFX
> 2. CZCE 2 字母 (TA/MA/SR/...) → CZC
> 3. SHFE 2 字母 (RB/CU/AU/...) → SHF
> 4. DCE 1 字母 (A/B/C/M/Y/...) → DCE
> 5. CFFEX 1 字母 T → CFX（兜底）

### 3.3 iFinD 字段 → FTS 字段映射（camelCase 别名）

| iFinD 字段 | FTS 字段 | 别名列表 |
|-----------|---------|---------|
| `openInterest` / `open_interest` / `OI` | `hold` | camelCase + snake_case + 大写 |
| `settle` / `settlement` | `settle` | 标准 |
| `preSettle` / `pre_settle` | `pre_settle` | camelCase + snake_case |
| `openInterestChg` / `oi_chg` / `open_interest_change` | `oi_change` | camelCase + snake_case 多种写法 |
| `amount` / `amt` / `turnover` | `amount` | 标准 |
| `volume` / `vol` | `volume` | 标准 |

> **与 Wind 的差异**：Wind 用 `oi` / `oi_chg`（简写），iFinD 用 `openInterest` / `openInterestChg`（全称 camelCase）。两者别名表独立维护，但通过相同 FTS 字段名汇流。

### 3.4 字段增强层降级策略

| 场景 | 行为 | 原因 |
|------|------|------|
| `is_available()` 失败 | 返回 `False` | 不影响主路径 |
| `fetch_ohlcv` MCP 连接错 | 抛 `SourceUnavailable` | 仍可被聚合器判定降级 |
| `fetch_ohlcv_or_none` 任何异常 | 返回 `None` | **覆写基类** — iFinD 失败不应熔断 K 线主路径 |
| `parse_ohlcv` 缺必填字段 | 返回 `None` | 优雅降级到无 iFinD 增强 |
| `fetch_edb` MCP 失败 | 返回 `None` | EDB 是辅助数据，失败不致命 |
| `amount` 缺失 | vwap 回退 `(h+l+c)/3` 典型价 | 与 TQ/Wind 路径一致 |

> **关键设计**：iFinD 适配器的 `fetch_ohlcv_or_none` 显式吞掉 `SourceUnavailable`（基类默认向上传播），确保 iFinD MCP 不可用时**不熔断**主 K 线路径。

### 3.5 vwap 计算公式

```python
vwap = amount / volume                    # 主路径（真实成交额）
vwap = (high + low + close) / 3           # 回退路径（典型价）
```

### 3.6 fetch_edb 独家能力（与 Wind/iFinD 差异化关键）

```python
def fetch_edb(self, indicator, start_date, end_date, trace_id):
    """EDB 宏观/产业链数据 — iFinD 独家能力，写入 edb_cache。"""
    query = f"{indicator}（{start_date}-{end_date}）"
    raw = _call_mcp(query)  # 调用 get_edb_data 工具
    return [
        {
            "indicator": row["indicator"],
            "indicator_name": row["indicator_name"],
            "date": row["date"],
            "value": row["value"],
            "unit": row["unit"],
            "yoy": row["yoy"],
            "source": "IFIND",
            "trace_id": trace_id,
        }
        for row in raw["data"]
    ]
```

> **iFinD 优势**：同花顺 EDB 覆盖国内/全球宏观、行业经济指标、大宗商品数据；Wind MCP 也有 mx_macro_data 但覆盖度不如 iFinD 细。

### 3.7 _call_mcp 入口设计

```python
def _call_mcp(query: str) -> Any:
    """调用 iFinD MCP 工具（bond_market_data / get_edb_data）。

    生产环境需通过 FTS 启动钩子注入真实 MCP 客户端。
    当前默认抛 RuntimeError，迫使 is_available() 返回 False（生产部署前需注入）。
    """
    raise RuntimeError("iFinD MCP 客户端未注入。...")
```

> **设计理由**：默认显式抛错（而非返回 mock 数据），避免生产环境静默使用假数据；通过 `patch("fts.data_sources.ifind_source._call_mcp", ...)` 在测试中注入 mock。
