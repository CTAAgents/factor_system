## 3. 实现要点

### 3.1 类结构

```python
class WindSource(BaseFuturesSource):
    source_name: str = "WIND"

    # 字段增强层 — 不参与 K 线主路径熔断
    def is_available(self) -> bool            # 探活（不抛异常）
    def fetch_ohlcv(...)                       # 抛 SourceUnavailable
    def parse_ohlcv(...)                       # 公开方法，可独立测试
    def parse_ohlcv_or_none(...)               # 异常 → None
    def fetch_ohlcv_or_none(...)               # 覆写基类，吞 SourceUnavailable
    def fetch_quote(...) / parse_quote(...)
```

### 3.2 Wind 字段 → FTS 字段映射

| Wind 字段 | FTS 字段 | 别名列表 |
|----------|---------|---------|
| `oi` / `open_interest` | `hold` | `oi`, `open_interest`, `hold` |
| `settle` / `settlement` | `settle` | `settle`, `settlement` |
| `pre_settle` | `pre_settle` | `pre_settle`, `prev_settle`, `pre_settlement` |
| `oi_chg` / `oi_change` / `open_interest_change` | `oi_change` | `oi_chg`, `oi_change`, `open_interest_change`, `oi_diff` |
| `amount` / `amt` / `turnover` | `amount` | `amount`, `amt`, `turnover` |
| `volume` / `vol` | `volume` | `volume`, `vol` |

### 3.3 字段增强层降级策略

| 场景 | 行为 | 原因 |
|------|------|------|
| `is_available()` 失败 | 返回 `False` | 不影响主路径 |
| `fetch_ohlcv` MCP 连接错 | 抛 `SourceUnavailable` | 仍可被聚合器判定降级 |
| `fetch_ohlcv_or_none` 任何异常 | 返回 `None` | **覆写基类** — Wind 失败不应熔断 K 线主路径 |
| `parse_ohlcv` 缺必填字段 | 返回 `None` | 优雅降级到无 Wind 增强 |
| `amount` 缺失 | vwap 回退 `(h+l+c)/3` 典型价 | 与 TQ 路径一致 |

> **关键设计**：Wind 适配器的 `fetch_ohlcv_or_none` 显式吞掉 `SourceUnavailable`（基类默认向上传播），确保 Wind MCP 不可用时**不熔断**主 K 线路径。

### 3.4 vwap 计算公式

```python
vwap = amount / volume                    # 主路径（真实成交额）
vwap = (high + low + close) / 3           # 回退路径（典型价）
```

### 3.5 _call_mcp 入口设计

```python
def _call_mcp(query: str) -> Any:
    """调用 Wind MCP 工具（mx_ashare_finance_data / mx_comprehensive_finance_data）。

    生产环境需通过 FTS 启动钩子注入真实 MCP 客户端。
    当前默认抛 RuntimeError，迫使 is_available() 返回 False（生产部署前需注入）。
    """
    raise RuntimeError("Wind MCP 客户端未注入。...")
```

> **设计理由**：默认显式抛错（而非返回 mock 数据），避免生产环境静默使用假数据；通过 `patch("fts.data_sources.wind_source._call_mcp", ...)` 在测试中注入 mock。

> **关键陷阱修复**：在端到端验证中发现 — 当 DataFrame 合并多行字段别名时（如第 3 行只有 `open_interest` 而前两行只有 `oi`），第一/二行 `open_interest` 列会被填 NaN。原始实现 `df.apply(lambda r: _pick(r.to_dict(), "hold"), axis=1)` 在第一行就会因 `oi` 已存在（值为 80000）而立即返回，跳过 `open_interest` 别名；但**对于第 3 行**，DataFrame 把 `oi` 列填为 NaN，NaN 通过 `is not None` 检查，导致 `_pick` 返回 NaN 而非 85000。**修复方案**：直接在原始 dict 列表上迭代 `[_pick(r, "hold") for r in rows]`，绕开 DataFrame 合并的 NaN 问题。
